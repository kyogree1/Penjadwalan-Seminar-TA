# R4 scheduling contract and verification

## Confirmed disagreements repaired

The original controller serialized Sempro registration `id` as candidate `id`; the optimizer returned that value as `mahasiswa_id`. Output omitted `pendaftaran_id` and `tipe`, and used `penguji1_id/penguji2_id` while publication expected `penguji_1_id/penguji_2_id`. Only administratively verified Sempro rows were selected, without R3 academic approval. Supervisor lists were empty, KBK was fixed to Informatika, and slots were fixed September dates. Fitness ignored its KBK bonus and had no workload objective. Double-booking compared identical date/start strings rather than intervals. Finite penalties still returned unconditional conflict-free success. The plan described roulette/bit-flip/swap, while code used tournament and slot/examiner-1 replacement. Publication was nontransactional, accepted unrelated identities, and had no role/readiness/supervisor/interval checks. Periods, overrides, GA logs, and apply were local simulations with leaked timers and invented metrics.

## Canonical contract

- Candidate: `pendaftaran_id` is a registration-table ID, `mahasiswa_id` a users ID, `tipe` is `sempro|sidang`; `(tipe, pendaftaran_id)` is the registration key. Candidate includes authoritative `supervisor_ids`, title, research field (`kbk`), student name/NIM, and persisted supervisor positions.
- Slot: `{tanggal: YYYY-MM-DD, jam_mulai: HH:mm:ss, jam_selesai: HH:mm:ss}`. Same-day half-open intervals; adjacent endpoints do not overlap. Explicit slots belong to a persisted selected period with type, wave, date bounds, capacity and open flag.
- Result: `period_id`, `outcome: complete|partial|infeasible`, `success` only for complete, `schedule`, `unscheduled`, fitness components, generations, actual logs and limitations. Infeasible means this bounded search returned no assignments, not a mathematical proof of global infeasibility. No optimality claim.
- Publication: `{period_id, schedules: [{pendaftaran_id, mahasiswa_id, tipe, penguji_1_id, penguji_2_id, tanggal, jam_mulai, jam_selesai}]}`. Generate rows can be mapped directly to publication; metadata does not authorize publication.
- Readiness: `status=verifikasi_tendik`, `status_akademik=disetujui`, matching period type/wave, student role, latest approved title with at least supervisor 1 and valid dosen supervisor IDs. Both Sempro and Sidang are supported through their typed periods. Active schedules remove candidates; repeat publication of the same active registration/period is idempotent. `terjadwal` is allowed only with the existing schedule on revalidation. Completed/assessed schedules cannot be republished or overridden.
- Publication locks dosen rows in stable order, then period/registration/schedule rows; the batch transaction rolls back schedules and registration transitions on any failure. It revalidates all IDs, period slots/capacity, examiner roles/distinctness, supervisor exclusion, and all draft/published/completed bookings across periods. Student, supervisor and examiner participants cannot overlap. Manual overrides share the same validation and cannot change registration identity. Existing legacy rows have nullable period IDs and remain visible in the historical/all list; they still block conflicting bookings.
- Period creation/edit uses real POST/PATCH endpoints. Date bounds and slot chronology are validated. Periods with any saved schedules are immutable in this bounded slice; archive/reopening policies are not silently introduced. No delete action. No dev database migration was run.

## Executable GA decision

Tournament selection k=3, inclusive two-point crossover, per-component integer random-reset mutation (slot plus both examiner preferences), elitism, feasibility decoder/repair. Neither roulette nor binary bit-flip applies to this representation. Coverage dominates fitness during selection. Soft fitness is `0.5 * exactKBKMatchRatio + 0.5 / (1 + maxExaminerLoad - minExaminerLoad)`. Existing workload is supplied to metrics; absent KBK contributes no matching credit. Decoder handles optional lecturer availability windows and capacities, distinct examiners, supervisor exclusion, participant interval overlaps and existing bookings. Tests seed mt_rand and exercise crossover/mutation at rate 1 for reproducibility.

## Explicit scope limits / blockers to unrestricted R4 acceptance

The audited users schema/model has name/NIP/prodi/jabatan but **no lecturer KBK, availability calendar, or quota storage**. Research field exists on PengajuanJudul. This change does not invent lecturer KBK from prodi/jabatan or invent free time/quota. Production controller returns actual lecturer directory metadata and measured booking workload; optimizer supports supplied real KBK/availability/capacity metadata and its tests verify their effects, but live KBK optimization and calendar/quota constraints remain unavailable pending a confirmed metadata storage/management contract (R5). Capabilities and result limitations explicitly expose this. Period capacity and persisted bookings are fully enforced. Consequently this is a verified bounded scheduling repair, not a claim that every original R4 requirement is closed.

Migration `2026_10_11_000003_create_schedule_periods.php` adds schedule_periods and nullable penjadwalan.period_id non-destructively, leaving historical rows unchanged. It is unapplied to the dev DB. Deployment needs the R3 migrations plus this migration before these endpoints are usable. Tests migrate SQLite :memory: only. Database-engine concurrency outside SQLite, authenticated browser acceptance and rubric/pass policies remain unverified. Excel/PDF/history actions are visibly unavailable (R5), not success-only toasts. plan.md belongs to the parent and was not edited.
