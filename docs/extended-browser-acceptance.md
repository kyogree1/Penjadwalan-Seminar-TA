# Extended isolated browser acceptance

## Outcome

Bounded real-browser acceptance completed for academic review, student uploads, logbook/paraf, GA publication/manual scheduling and two-examiner completion. **Not production signoff or password-reset completion.** Real headless Edge/Playwright exercised business buttons, native selects, text forms and file inputs against a newly migrated scratch SQLite database at port 8898. No commits or application-source edits. Latest `bun run build` succeeded; optional fontaine warning remains.

Evidence: `docs/extended-browser-evidence/` contains reusable `router.php`, `harness.cjs`, guarded `fixture.py`, replay `actions.json`, numbered DOM/control snapshots and screenshots, `events.jsonl`, `log-summary.json`, `persistence.json` and `cleanup.json`.

## Limitations and findings

- **Sidang correction/retention is not accepted.** After requesting academic revision, attempted correction found no expected editable text input (43 diagnostic timeout). Approval was subsequently performed on the unchanged registration, not a claimed corrected submission. Needs dedicated UI investigation.
- Sempro student status becomes Selesai but still displays empty registration history and empty execution/results (47), despite persisted registration/completed schedule. This is a presentation/read-contract gap, not missing score persistence.
- Duplicate `NIM: NIM:` remains visible. Sidang Turnitin UI advertises 10 MB; earlier contract documentation describes 5 MB. File-size boundary behavior was not tested here.
- PDF response `body()` is an Edge PDF-viewer HTML wrapper, **not original PDF bytes**. Those artifacts were renamed `*.viewer.html`. Do not use their recorded hashes as document byte-integrity proof. Private storage hashes independently match uploaded input; actual document security headers are verified. Human PDF rendering/content inspection remains unverified.
- Forgot submission 54 captured `Memproses...` only; it does not establish redirect, token issuance, delivered mail, reset completion or new-password login. No password/token entered; no real mail delivery was exercised. Earlier guest/authenticated selector diagnostics 51–52 are not passes.
- Period creation/edit controls, capacity boundary rejection, concurrent cross-engine booking, full document-denial matrix and all-portal accessibility/responsive acceptance remain unverified here. Periods were fixtures. Parent-owned backend/SFC tests are separate evidence.
- No browser pageerror events observed. Five resource-404 console errors occur in 14; builds ran during acceptance, so no zero-console-error claim. Wrong button-label/file-index/login-state diagnostic timeouts remain in logs and error screenshots and are not successful acceptance. Each successful result above has a subsequent snapshot/reload or persistence readback.

## Replay

Create fresh scratch directory/database and install Playwright there (`npm install --prefix <scratch> playwright`). With explicit `DB_CONNECTION=sqlite`, scratch `DB_DATABASE`, `APP_ENV=local`, `CACHE_STORE=array`, `SESSION_DRIVER=file`, migrate/seed; use functioning Herd PHP (native WinGet PHP lacked SQLite driver in this run). On this Windows host Herd requires a PTY wrapper for CLI execution. Execute guarded fixture.py with Python, start the isolated router on 8898 with `ACCEPTANCE_SCRATCH`, then run `node docs/extended-browser-evidence/harness.cjs <role> <route> <new-label> '<actions JSON>'`. `guest` skips demo setup. Replay business actions from actions.json using fresh labels; role-switch fixture adjustments described above are prerequisites, not encoded business interactions. Do not replay actions blindly into development data. Stop only owned server, verify connection refusal, close SQLite handles, then remove scratch.
